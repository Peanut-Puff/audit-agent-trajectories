# Trial 人工语义时序与报告格式

适用于单 Trial、一对 Trial 和 Job 下钻详情的 `standard|full` 深读。整个 Job 的阶段概览仍首选[自动 E/B/I/V/P](round-analysis.md)，不要求先为所有 Trial 人工分段；`metrics` 不生成语义解释。用户显式选择其他口径时遵从用户。

## 按真实工作变化切段

完整阅读原生主轨迹的请求、reasoning、工具参数与 observation，再归纳有界摘要。以工作目标、方案承诺、关键反馈或交付状态发生变化作为边界；不要将工具名、固定轮数或 E/B/I/V/P 字母换个中文名当作语义分段。

例如一段类型系统任务可以分为：理解 wrapper/推断接口 → 自引用方案实验 → 有界展开可行性 → 核心 API 与 parse 接入 → 泛型编译集成修复 → runtime 测试 → 类型断言返修 → 首次全库验收 → 深度参数实验 → 联合类型扩展及回退 → 最终候选验证 → 提交。它们是粒度示例，不是固定流水线、阶段数量或适用于其他任务的结论。简单 Trial 可以只有几段；复杂返修应保留独立子段。

每段记录：中文标题、工作目标、关键动作、观察结果、session、连续请求范围、请求数、工具数、可证时间窗口、input/output/reasoning/cache/非缓存输入及各项缺失数、标注方法、证据位置、限制。不要把本轮动作和下一轮读到的结果错配；允许“R35 执行检查、R36 读到结果”的边界说明。

- 每个阶段限于同一 session 中连续的已观察请求；按时间顺序列出，不能重叠、乱序或跨会话拼接。
- 尽可能覆盖原生主请求一次；未覆盖请求、辅助请求、缺失 usage、与总账的差额单列，不能补零或分摊到阶段。
- 同目标多次重开时保留各自的时序段，如“首次类型实验”“全库通过后深度实验”。“通过”只描述当时具体 scope/revision，不替代最终 verifier。
- 管道、尾部 echo 或 runner 裁剪可能掩盖失败；不能只按 shell exit code 判断验收，也不能把临时 probe 当成功交付。
- 时间来自已观察边界时称“窗口”，说明包含工具与调度，不称纯模型/工具耗时；缺少时间保留未知。

## 配对时先保留顺序，再按目标对齐

双方各自一列展示真实顺序，段数可不同。另给同目标对齐表，明确两侧请求范围、资源、结果和为什么可对齐。允许多个不相邻阶段在对齐表归入一个目标，但必须列出全部原范围；不改写原时序，不按阶段编号配对。

一侧缺少对应工作时写“无独立对应段”，不要填 0。同名不自动证明工作量或覆盖等价；首次测试、全库测试、扩大 scope、增加断言与删改断言须在结果摘要中区分。双方都成功时解释效率机制，不强加失败根因。

对齐表默认同时展示各目标差额和占总差异比例，并随所选指标切换：`目标差额 = 右侧 − 左侧`，`占比 = 目标差额 / 同范围总差额`。明确分母是公共总账还是已观察主请求小计；辅助/未归属的差额与占比另列并对账。负值表示抵消，允许超过100%；总差额为0时占比无定义，不能强行归一化成正数。它是账目分解，不是因果贡献。

一侧无标注不等于真实无该工作，默认不算差额。只有完整主请求分区加原始证据确认一侧独有时，才允许把该目标的单侧用量归入差额，标注“独有工作归集”，同时仍将对应阶段显示为空。比较资格、token语义或覆盖不足时不显示占比。

## Token 解释

遵循[Token 与成本](token-and-cost.md)，先对齐原生逐请求 usage 与公共总账再计算阶段。记录原字段、转换公式与证据，不能仅凭 adapter 名猜测缓存和 reasoning 的包含关系。保持原始账本不变，派生转换单独留 provenance。

分析顺序：总量/完整性 → 请求数 × 平均输入 → 语义阶段热点 → 关键决策与返修 → 固定 prompt、历史 reasoning、工具 schema/结果和批处理方式。只有有完整 request body 时才分析其组成；字符占比不能当 token 占比。缓存读取增量、非缓存输入和输出分开报告，不用累计输入倍数替代费用倍数。

`input = 请求数 × 平均每次 input` 以及对差额的对称算术分解可以帮助解释数量级，但不是独立因果贡献。机制结论至少提供直接证据、最强替代解释、置信度和限制；不能把全部通过后工作或账本差额称为浪费。

## 默认交付形态

正文和 HTML 共用人工分段、测量与 findings；不在正文或 HTML 内嵌每个 turn 原文、完整 reasoning、prompt、工具参数/输出，即便默认折叠也不复制它们。

1. 范围、结果、可比性和简短主结论，区分测量与机制。
2. **人工语义时序**：双方独立列；标题、范围、请求/工具数、关键动作、结果；共用刻度的消耗条可切 input、output、reasoning、非缓存输入、请求和时间窗口。
3. **同目标对齐表**：显式多段映射与未对应段；差值/倍数仍遵守比较准入。
4. **请求曲线**：累计输入、单次输入长度、累计输出、累计 reasoning、累计非缓存输入五项；序号/可证时间切换、悬停、键盘操作与证据下钻。缺失处断线，多会话分开。
5. **差异机制**：关键方案决策、历史上下文放大、工具碎片化、返修/重复验证、提示词等有证据的因素；直接证据、替代解释和局限可从抽屉查看。
6. 有证据的可复用控制与验收方式；总账对齐、health/coverage、verifier、交付及未知项保留入口。

使用[HTML 展示层](../html-presentation.md)的通用渲染器、`trial-presentation/1` 标注和现有蓝/陶土橙资产；无需复制某个任务的分析脚本或硬编码该任务的阶段。阶段标注只能来自深读，渲染器不能从工具类别补写语义。

## 完成检查

- 阶段成员无重叠、无错序；未归属与缺失显式列出，阶段和等于已观察主会话小计。
- 逐请求小计与公共总账对齐；辅助/未归属请求差额单列；cache/reasoning未重复相加。
- 同目标对齐是人工映射，合并不影响原时序；一侧缺失未写成0。
- 报告中无逐turn原文；证据位置可回到原始包 member、session、round/tool ID、行号或hash。
- HTML 单文件离线，实际运行检查阶段切换、曲线五项、证据抽屉和窄屏布局；没有原始数据的指标显示缺失。
